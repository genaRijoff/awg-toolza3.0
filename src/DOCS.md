# AWG3 — менеджер AmneziaWG 3.0

Ставится **рядом** с AWG 2.0 (`awg2.sh` / AWG Toolza) и не ломает его.
Backend — userspace `amneziawg-go`, не DKMS-модуль.

Статус: рабочее управление. Сервер, клиенты, конфиги, полное удаление.

**`S1`–`S4` не ниже 12 при включённом AWG 3.** `HeaderCipherNonceSize = 12`:
nonce для ChaCha20 берётся из первых 12 байт S-паддинга. При меньшем значении
срез уходит в тело сообщения — падения нет, но шифр молча слабеет. README
amneziawg-go называет цифру 8, это неверно.

**Backend подтверждён.** Все семь UAPI-ключей AWG 3 приняты живым
`amneziawg-go/v3` на Ubuntu 24.04. `header_protection_key` идёт в UAPI как
**hex 32 байта** (в JSON sing-box тот же параметр — base64, не перепутать)
и требует `S1`–`S4` ≥ 8, иначе `EINVAL`.

| Модуль | Назначение | Тесты |
|---|---|---|
| `awg3/paths.py` | пути и константы изоляции от AWG 2.0 | косвенно |
| `awg3/core/uapi.py` | клиент UAPI-сокета amneziawg-go | частично |
| `awg3/core/keys.py` | реестр UAPI-ключей + уровень доверия | да |
| `awg3/core/wgkeys.py` | ключи X25519, base64 ↔ hex | да |
| `awg3/core/models.py` | доменные модели и все инварианты | да (33) |
| `awg3/core/backend.py` | запуск amneziawg-go, настройка интерфейса | частично |

Признак поднятого линка читается из флагов `<...,UP,...>`, а не из `state UP`:
TUN-устройства держат operstate `UNKNOWN` даже полностью рабочими.
`configure_link` проверяет результат `ip link set up` и падает с внятной
ошибкой, если линк не поднялся — иначе `amneziawg-go` не откроет UDP-сокет,
и это выглядит как «всё хорошо, но клиенты не подключаются».
| `awg3/core/probe.py` | проверка имён ключей AWG 3 на живом бинаре | нужен root |
| `awg3/core/storage.py` | SQLite — источник правды | да |
| `awg3/core/profiles.py` | генератор Jc/S/H и параметров AWG 3 | да (1500 генераций) |
| `awg3/core/presets.py` | шаблоны настроек, DNS, MTU | да |
| `awg3/core/cps.py` | генератор I1-I5 (TLS / QUIC / DNS) | да (8000 генераций) |
| `awg3/core/export.py` | клиентский `.conf` | да |

**Для AWG 3.0 нужен AmneziaWG β, а не основное AmneziaVPN.** Импортёр
`importController.cpp::extractWireGuardConfig` переносит из `.conf` только
`Jc/Jmin/Jmax/S1/S2/H1-H4` и `S3/S4/I1-I5`. `HeaderProtectionKey` и шесть
таймингов AWG 3 молча выбрасываются, `protocolVersion` принимает лишь `"1.5"`
и `"2"`. Потеря `HeaderProtectionKey` фатальна: сервер шифрует заголовки,
клиент нет, handshake initiation не разбирается — соединение не поднимается
без внятной ошибки. Отдельное приложение AmneziaWG β импортирует `.conf`
корректно, включая параметры AWG 3.

`AllowedIPs` — только `0.0.0.0/0`. IPv6 в туннеле не выдаётся, и `::/0` здесь
означал бы чёрную дыру: трафик к AAAA-хостам уходил бы в интерфейс без
IPv6-адреса и висел до таймаута. `PersistentKeepalive` — диапазон при
включённом AWG 3, иначе одиночное значение: диапазон понимают только
клиенты с поддержкой AWG 3.
| `awg3/core/network.py` | INPUT, NAT, forward с тегом `awg3`, ufw | частично |

Правило INPUT для UDP-порта обязательно: FORWARD и NAT пропускают трафик
*через* сервер, а пакет клиента приходит *на* сервер и упирается в INPUT.
Вставляется через `-I`, а не `-A`: у ufw в конце INPUT уже стоит DROP, и
дописанное после него правило не сработает никогда. Если ufw активен, порт
дополнительно открывается его же командой — иначе при перезагрузке ufw
пересоберёт свои цепочки и наше правило исчезнет.
| `awg3/cli/actions.py` | подъём и остановка без интерактива (для systemd) | нужен root |
| `awg3/cli/menu.py` | интерактивное меню | нужен root |

### Автозапуск

`awg3.service` — `Type=oneshot` с `RemainAfterExit=yes`, `ExecStart=awg3 --up`.
Не шаблонный юнит и не голый демон: `--up` делает полный подъём — демон,
адрес, конфигурация через UAPI, правила сети. Иначе после перезагрузки
интерфейс встаёт без параметров и клиенты не подключаются.

Меню и юнит дёргают один и тот же код из `actions.py`, поэтому поведение
после ребута не может разойтись с поведением после «пункт 3». Юнит включается
автоматически при первом успешном запуске туннеля.

```bash
systemctl status awg3
sudo awg3 --up      # то же, что пункт 3
sudo awg3 --down
```
| `install.sh` | установка, обновление, удаление | да (64) |

## 0. Быстрый старт на сервере

Одной командой:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/USER/awg3/main/install.sh) --install
```

Либо из клона:

```bash
git clone https://github.com/USER/awg3 && cd awg3
sudo bash install.sh --install
sudo awg3-probe      # проверка поддержки AWG 3
sudo awg3            # меню управления
```

## Раскладка

```
install.sh     единственный файл в корне
src/           всё остальное
```

`install.sh` кладёт `src/` в `/opt/awg3/src` и дальше работает оттуда.
При `--update` папка обновляется через `git fetch`, а если она пришла
не из git — скачивается заново. Запуск через `curl` без клона работает
потому же: скрипт сам достанет репозиторий.

### Меню `sudo awg3`

| | Пункт |
|---|---|
| 1 | Создать сервер — адрес определяется сам, настройки по шаблону |
| 6 | Перегенерировать обфускацию — клиенты и ключи сохраняются |
| 2 | Показать конфигурацию сервера |
| 3 | Запустить интерфейс (UAPI + адрес + NAT) |
| 4 | Остановить интерфейс |
| 5 | Состояние: пиры, правила, ip_forward |
| 7 | Добавить клиента — ключи, адрес, применение на лету |
| 8 | Список клиентов |
| 9 | Показать конфиг клиента |
| 10 | Включить или выключить клиента |
| 11 | Удалить клиента |
| 12 | Полное удаление конфигурации (для переустановки) |
| 0 | Выход |

**Создание сервера.** Внешний адрес определяется автоматически: `ip route get`
спрашивает у ядра, с какого адреса сервер уходит наружу. Если адрес приватный
(сервер за NAT облачного провайдера), тулза обращается к внешнему сервису.
Оператору остаётся нажать Enter.

Остальное — шаблоном:

| Шаблон | Профиль | AWG 3 | MTU |
|---|---|---|---|
| Рекомендуемый | standard | да | 1420 |
| Максимальная маскировка | pro | да | 1380 |
| Скорость | lite | да | 1420 |
| Совместимость | standard | нет | 1380 |

Пятый пункт — подробная настройка: профиль, DNS (Cloudflare / Google / Quad9 /
AdGuard / свой) и MTU по отдельности. Перед созданием показывается сводка
и запрашивается подтверждение.

Опасные пункты подтверждаются `[y/N]` латиницей — на телефоне раскладка может
быть любой, и требовать ввод кириллического слова было бы издевательством.
Умолчание везде «нет»: случайный Enter ничего не сносит. Полное удаление
спрашивает дважды.

После каждого действия — пауза до нажатия Enter, иначе вывод пролетает и
главное меню перерисовывается прежде, чем его успеешь прочитать.

Установщик делает всё сам: зависимости, Go нужной версии, сборка
`amneziawg-go` в `/opt/awg3/bin`, venv с `cryptography`, systemd-юнит,
самотест. Плюс preflight — читает `awg0.conf` и резервирует порт и подсеть,
не пересекающиеся с AWG 2.0.

| Ключ | Что делает |
|---|---|
| `--install` | установка без вопросов |
| `--update` | пересобрать бинарь и ядро, `/etc/awg3` не трогать |

`--update` рассчитан на уже установленный сервер: он не делает preflight, но
юнит и утилиты переустанавливает — их определения меняются между версиями, и
молчаливый пропуск оставлял систему без автозапуска. На чистой машине нужен `--install`. Недостающие утилиты
(`git`, `make`, `curl`, `python3`) обе команды догоняют сами — раньше
`--update` падал на отсутствующем `make` уже после скачивания Go, оставляя
половину установки.
| `--uninstall` | удалить, **конфиги сохранить** |
| `--uninstall --purge` | удалить вместе с `/etc/awg3` |

Удаление гасит интерфейсы AWG3 и снимает правила `iptables` с тегом `awg3` —
адресно, по одному, разбирая `iptables-save`. Правила без нашего тега не
трогаются: там могут быть AWG 2.0, Warp и каскад. `/var/log/awg3.log`
сохраняется намеренно — после аварии это единственный след.
| `--probe` | проверить имена UAPI-ключей AWG 3 |
| `--test` | самотест моделей |
| `--dry-run` | показать план и выйти |

Повторный `--install` **не меняет** зарезервированные порт и подсеть: они
берутся из `/etc/awg3/reserved.env`. Смена порта на переустановке тихо
оборвала бы всех клиентов с уже розданными конфигами. Сбросить резерв —
удалить этот файл.

Тесты самого установщика (без root, ничего не ставят):

```bash
bash test_install.sh     # 64 проверки установщика
python3 test_core.py     # 52 проверки ядра, шаблонов, детекта адреса
```

Это возможно за счёт библиотечного режима: `AWG3_INSTALL_LIB=1 source install.sh`
определяет функции, но не запускает `main`.

## 1. Тесты без root и без сервера

Ничего не ставит, ничего не трогает. Можно прямо на рабочей машине.

```bash
tar -xzf awg3-skeleton.tar.gz && cd awg3
python3 --version            # нужен 3.11+ (используется slots=True, strict=True в zip)
python3 -m pip install cryptography --user   # единственная зависимость ядра
python3 test_models.py
```

Ожидаемо: 33 строки `OK` и `ИТОГО: ВСЕ ПРОШЛИ`.

**Что именно проверяется** — если какая-то строка упадёт, смотри сюда:

- генерация X25519 и вывод публичного ключа без `awg genkey`
- round-trip base64 ↔ hex (главный источник ошибок при работе с UAPI)
- `S1+56 ≠ S2` — запрет из мануала AmneziaWG
- пересечение диапазонов `H1`–`H4`
- `Jmax < MTU` — иначе junk-пакет фрагментируется и демаскирует туннель
- `Jmin < Jmax`
- header protection требует `S1`–`S4` ≥ 8
- `RekeyAfterTime < RejectAfterTime` — сессия обязана сменить ключи раньше, чем её отвергнут
- деградация рендера: неподтверждённый ключ выкидывается, остальной набор доезжает

Быстрая ручная проверка моделей:

```bash
python3 -c "
import sys; sys.path.insert(0,'.')
from awg3.core import keys
for k in keys.AWG3_KEYS:
    print(f'{k.uapi:<26} {k.confidence.value:<13} {k.note}')
"
```

## 2. Сборка backend вручную

`install.sh` делает это сам — раздел на случай, если надо руками.
Собираем в собственный префикс: системный `amneziawg-go` ставить нельзя,
его снесёт деинсталлятор AWG 2.0 (`apt-get remove amneziawg-tools`).

Требуемая версия Go читается из `go.mod` склонированных исходников, а не
задаётся константой — upstream её поднимает. Если системный Go младше,
установщик тянет официальный тарбол в `/opt/awg3/go` с обязательной проверкой
sha256. Системный Go при этом не трогается. Если go.dev недоступен, есть
откат на встроенную докачку toolchain (нужен Go >= 1.21 и `GOTOOLCHAIN != local`).

```bash
sudo apt-get update && sudo apt-get install -y golang-go git
git clone https://github.com/amnezia-vpn/amneziawg-go /tmp/awg-go
cd /tmp/awg-go && make

sudo mkdir -p /opt/awg3/bin
sudo install -m 0755 amneziawg-go /opt/awg3/bin/amneziawg-go
/opt/awg3/bin/amneziawg-go --version 2>&1 | head -1
```

Проверь, что в исходниках вообще есть AWG 3:

```bash
grep -rn "HeaderProtectionKey\|header_protection" /tmp/awg-go/device/ | head
```

Пусто → собран не тот коммит, AWG 3 не будет.

## 3. Probe — главный тест этого этапа

Закрывает единственный непроверенный вопрос: как в UAPI называются ключи AWG 3.
Поднимает одноразовый интерфейс `awg3probe`, выставляет базовый набор AWG 2.0
(`S1`–`S4` ≥ 8 — иначе header protection отвергается по причине, не связанной
с именем ключа), пробует каждый ключ AWG 3 и гасит интерфейс.

Отдельно проверяется форма `H1`–`H4`: диапазон `a-b` против одиночного
значения. В базовый набор они не входят намеренно — это как раз то, что
проверяется. В AWG 2.0 `H1`–`H4` заменяют константы типов сообщений 1/2/3/4,
и принимает ли демон диапазон, нигде не задокументировано.

Для `header_protection_key` перебираются форматы значения: hex 32 байта,
base64 32 байта, hex 16 байт, произвольная строка. UAPI отвечает одинаковым
`EINVAL` и на неизвестное имя, и на негодное значение — различить их можно
только перебором.

```bash
sudo awg3-probe
```

**Как читать вывод:**

| Результат | Что значит | Что делать |
|---|---|---|
| все 7 `√` | сборка поддерживает AWG 3 | идём дальше |
| строка `h1-h4` | в какой форме демон принимает заголовки | см. ниже |
| `header_protection_key` `×`, остальные `√` | имя верное, не подходит формат значения | probe печатает, что пробовал; см. `device/uapi.go` |
| все 7 `×` | бинарь собран без AWG 3 | `grep` из шага 2, потом пришли вывод |
| `UAPI-сокет не появился` | демон не стартовал | см. ниже |

Если демон не поднимается — смотри его напрямую:

```bash
sudo LOG_LEVEL=debug /opt/awg3/bin/amneziawg-go -f awg3probe
```

Прибрать за собой, если probe упал на середине:

```bash
sudo ip link delete dev awg3probe 2>/dev/null
sudo rm -f /var/run/amneziawg/awg3probe.sock
```

## 4. Проверка сосуществования с AWG 2.0

Прогнать **до** и **после** probe, вывод должен совпасть:

```bash
# AWG 2.0 жив?
sudo awg show awg0 | head -5
systemctl is-active awg-quick@awg0

# наши пути ничего не задели
ls -la /etc/amnezia/amneziawg/          # awg0.conf на месте
ip route show table 200 | head          # таблица Warp не тронута
sudo iptables -S | grep -c awg3         # должно быть 0 на этом этапе
```

Что должно остаться нетронутым: `/etc/amnezia/`, таблица маршрутизации `200`,
интерфейс `awg0`, порт из его `ListenPort`, правила UFW с меткой AmneziaWG.
